# Bounded bilingual lexical admission v0.1

User authorization: «Следующий этап — устранение необоснованных лексических
отказов. - выполняй». Offline implementation and controls, no new model/OAuth
allowance. All previous live scopes remain closed.

Freeze before edits: all current app Python/YAML hashes, exact service source,
the30 post-metadata-correction preparations and their question-only input.
These are exposed regression cases, not independent evaluation. Do not consume
reference answers as program inputs or add authors, case IDs, article IDs, answer
values, page numbers, or expected result counts to application logic.

Implement an additional lexical admission path for direct Russian field requests
whose original baseline fails only insufficient_distinctive_term_coverage.
Initial vocabulary: synthesis, yield, purity, purification, viscosity, activation
energy; auxiliary ordering and ether-class cues. Phrase equivalence is lexical,
not claim truth/experimental ownership/completeness validation.

Preconditions: exactly one explicit author/year reference, uniquely resolved by
the unchanged registered metadata resolver; all evidence belongs to that exact
article and the resolution metadata matches the question. Recompute per-request
coverage from original evidence. No external translation/rewrite, ranking,
retrieval, source, prompt, threshold, DB or PDF changes.

Every substantive question token must belong to a recognized phrase, a small
explicit function-word set, a named Latin chemical identifier or a handled item
count. Require at least two distinct primary property concepts. All concepts and
all named identifiers must occur together in one unchanged raw fragment; emit
exact raw offsets/text hashes/citation bindings for every match. Substring-only
identifier matches, cross-fragment phrase joins and unrecognized question tokens
cannot upgrade refusal. For an explicit enumerated item count, require a literal
ordered identifier chain of that size in the same fragment (no inferred units,
temperature or ownership). Preserve original baseline metrics separately.

Questions with causal/epistemic/negated/universal wording are unsupported by this
path. No statement can become accepted scientific knowledge merely through
lexical coverage. Explicitly excluded non-observation/hypothesis/reference-only
regions cannot supply the new field matches. Leave required-concept/relation,
specialized quote/fact/fidelity/superlative/Methods and provider validators intact.
Previously admitted cases remain unchanged; unsupported cases retain their refusal
and diagnostics distinguish unrecognized grammar from absent source fields.

Controls: constructed positive requests with different names/identifiers/values,
RU inflections and ligatures; missing each field/identifier, substring traps,
different articles, unresolved/mismatched reference, split phrases/fragments,
unknown method/conditions/numeric constraints, causal/status requests, empty
evidence, previous-work/hypothesis/unperformed-measurement source cues and item
count mismatch. Test actual service positive/negative/provider-call boundaries
with synthetic provider results, separate from real model answers. Run relevant
regressions, Ruff, full app mypy. Compare all30 frozen preparations plus old
service-channel regressions; preserve selected source identities/raw text, native
input bytes for already-ready cases, and all old stored results/manifests.
Use fresh read-only preparations if available. No sends or slot reservations.

Report before/after availability separately from scientific accuracy; list every
newly admitted/refused case and unresolved limitation. No automatic live pilot.
