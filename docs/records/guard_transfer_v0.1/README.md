# Новые вопросы после фиксации защиты

Вы заранее подготовите эталоны. Пока ни новые вопросы, ни эталоны, ни новая
выборка не зарегистрированы. `registration_template.json` пустой; лимит вызовов0.
Этот transfer check не заменяет отдельный прежний24-task evidence-workflow pilot.

1. Подготовьте новые вопросы и ответы по исходным статьям до просмотра новых
   ответов ARIADNE. В эталоне сохраните необходимые пункты, числа/единицы/условия,
   объект и статус утверждения, цитаты и PDF pages, допустимые неоднозначности
   и случаи недостатка данных. Не подгоняйте эталон под текущую грамматику.
2. Эталоны оставьте вне общего рабочего каталога, отдельно от вопросов. Укажите
   автора, использование LLM/экспертной проверки и видел ли автор новые ответы
   именно этих случаев. Не объявляем независимость только по имени файла.
3. До запуска зафиксируйте SHA256 личного файла эталонов и передайте только hash
   и metadata подготовки. Hash подтверждает неизменность позже предъявленного
   файла, не его научную правильность/авторство. Содержимое не читается inference
   worker. Хранение вне каталога само по себе не является проверенной ACL.
4. Публично передайте каждый вопрос дословно и статью (article ID/DOI/PDF).
   Для каждого случая нужны уникальный case ID, original PDF SHA256 и declared
   exposure: новая статья или новый вопрос к известной статье. Последнее не
   считается переносом на новую литературу. Не включайте ответы/цитаты-ответы
   в public question manifest.
5. После получения публичных вопросов зафиксируем весь cohort и commitments
   до первых ответов; source eligibility не зависит от успеха finite checker.
   При изменении code freeze тест откладывается: новая версия и отдельный scope.

Измерение: один raw ответ экспериментального provider и решение guard на том
же ответе/источниках, без второго model draw для «baseline». Это не сравнение
с production /answer или недельной старой версией. Все вопросы входят в
denominator, включая исходный refusal/unsupported family/unknown grammar.
Отдельно оцениваются raw научная полнота/ошибки, coverage guard, удержание
неподтверждённых ответов и ложное удержание корректных. Unknown-wording label
не освобождает от учёта false holds по человеческому эталону. Независимая
научная оценка/accuracy пока не выполнена; протокол не обещает статистической
мощности. После запуска не менять код на новых test cases до окончания оценки.
