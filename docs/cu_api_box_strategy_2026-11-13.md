## 1. Уточнение продуктовой стратегии

Утверждение пользователя 17 ноября: веб-сервис ARIADNE предоставляется
по подписке с включённым лимитом вычислений, поставщику российского API
платит оператор ARIADNE. Клиент вносит единый платёж оператору. Цена,
период, лимит и порядок пополнения пока не выбраны. Это коммерческая модель,
не разрешение новых оплат/обращений и не подтверждение готового биллинга.

Пользователь предложил рассмотреть сборку ПК для BOX-версии и два варианта
продукта: онлайн через API и полностью offline BOX. Прежняя осторожная
API-first стратегия не является запретом на такой вариант заявки.
Текущая цель проработки — одно ядро с двумя профилями исполнения,
а не две независимо разрабатываемые системы.

| Профиль | Предполагаемая поставка | Граница обработки |
| --- | --- | --- |
| ARIADNE API | Целевая коммерческая веб-версия на инфраструктуре оператора, подписка с включённым лимитом вычислений | Клиент загружает свой корпус оператору; выбранный контекст передаётся российскому ИИ-провайдеру, которому платит оператор; сеть нужна |
| ARIADNE BOX | Экспериментальная рабочая станция с предустановленным ПО и моделями; доступ с неё или по локальной сети | Весь объявленный процесс выполняется локально после подготовки поставки; внешние сервисы не требуются |

Таблица описывает целевые профили. Многопользовательский хостинг, биллинг,
изоляция клиентов и коммерческая автономность BOX здесь не реализованы
и не испытаны. Для веб-загрузки клиент выбирает файлы/папку и передаёт
файлы серверу; одного пути к папке на ПК недостаточно. Постоянная синхронизация
не выбрана. Коммерческое направление не расширяет годовую приёмку BOX.

Общие компоненты: хранение документов, OCR/текстовые слои, chunking,
индексы/поиск, отбор evidence, схема записей/проверок, review и экспорт.
Для BOX нужен отдельный локальный inference adapter и проверка всех
вспомогательных стадий. API factory сейчас использует GigaChat; локальный
полный workflow ещё не реализован/не принят как готовый результат.

Российское происхождение ИИ и автономность — отдельные требования.
Разрешённые локальные модели, лицензии и происхождение каждого ИИ-компонента
фиксируются. Наличие зарубежного производителя GPU само по себе не означает
обязательного зарубежного сервиса; требований к отечественному происхождению
всех аппаратных компонентов пользователь не задавал.

## 2. Почему приобретение ПК может иметь предметное обоснование

Если в программе работ действительно предусмотрены разработка и испытание
автономного BOX, станция становится экспериментальным образцом и средством
выполнения конкретных испытаний: работа без сети, локальный inference,
воспроизводимая установка, ограничение памяти, длительная нагрузка,
резервное копирование и применение в контуре предприятия.

Нужно показать, почему имеющиеся ресурсы и API не позволяют выполнить именно
эти испытания, какую измеримую задачу решает каждый существенный компонент
и что останется по итогам: собранный образец, конфигурация, ПО/модели,
инструкции и отчёт. Само название «экспериментальный ПАК» не делает расход
допустимым и не является научной новизной.

На [странице программы](https://cu.ru/science/translationresearch) заявлена
поддержка превращения исследований в работающие прототипы. По
[Положению от 24 сентября 2026](https://static.centraluniversity.ru/documents/legal/common/polozhenie-programma-ti-cu.pdf),
приложение №2, стр. 10, закупка оборудования допускается в исключительных
случаях по отдельному запросу. Поэтому реальное назначение BOX даёт основание
подготовить запрос, но не гарантирует согласование закупки.

До окончательного бюджета уточнить: допустимость комплектующих/сборки/услуг,
порядок закупки и учёта, собственник оборудования, место размещения и режим
передачи/доступа на пилоте, дальнейшее использование после проекта.
Личный переход права собственности пользователю не предполагается и не установлен.
Для третьих исполнителей применяются условия письменного согласования.

## 3. Реализуемость локального российского ИИ

Проверены официальные model cards разработчика:

- [GigaChat3-10B-A1.8B](https://huggingface.co/ai-sage/GigaChat3-10B-A1.8B);
- [GigaChat3.1-10B-A1.8B](https://huggingface.co/ai-sage/GigaChat3.1-10B-A1.8B).

Они описывают открытые веса и локальный inference; в карточках указана MIT.
Это первичное основание рассматривать локальный российский LLM как
кандидата. Конкретный checkpoint/revision и файлы лицензии нужно закрепить
при выборе. Работа на наших задачах, язык источников, структурированный
вывод и пригодность для BOX не проверены; модель не выбрана и не скачивалась.
Заявление о поддержке локального запуска не является доказательством
конкретной GPU-конфигурации или качества извлечения.

В прототип допускается выбирать несколько кандидатов на development-этапе,
но обязательства по работе только с российскими ИИ сохраняются. Иностранная
модель на российском хостинге не переименовывается в российскую.

## 4. Годовой результат BOX: сборка и отладка стенда

Текущий выбранный состав: собранное совместимое оборудование, базовая
подготовка ОС/драйверов, отладка стабильности, конфигурация и протокол
выполненных проверок. Конкретные тесты и исполнитель уточняются. Это стенд
для дальнейших локальных экспериментов; готовый автономный литературный
QA-продукт и измеренное научное качество локальной модели не обещаются.

Обучение с нуля и дообучение не являются автоматически включёнными работами.
Предлагаемый следующий технический путь — запуск готовой предобученной
модели и подключение RAG. В RAG найденные фрагменты статей поступают в контекст
генерации, обновление корпуса не требует обязательного переобучения весов:
[документация Transformers/RAG](https://huggingface.co/docs/transformers/model_doc/rag).
Это архитектурная возможность, не подтверждение качества ARIADNE на BOX.
Сохранённая Qwen 27B — кандидат, не выбранная/испытанная модель.

Дообучение LoRA/QLoRA меняет небольшие адаптеры и может уменьшать требования
к памяти по сравнению с полным дообучением, но требует данных, подготовки
эксперимента и отдельной проверки качества:
[документация PEFT](https://huggingface.co/docs/transformers/peft).
Ни достаточность 32GB VRAM для выбранного обучения, ни необходимость
такого обучения не установлены. Никаких весов/обучений/прогонов сейчас нет.

### Раннее более широкое предложение — дальнейшее направление

Предлагаемый текст:

> Разработать и экспериментально оценить ARIADNE с двумя профилями исполнения:
> через российский ИИ API и в автономном локальном контуре. Для автономного
> профиля создать один экспериментальный BOX-образец с предустановленным ПО
> и локальными моделями. На одинаковом согласованном сценарии подготовки
> обзора электролитов NMC / графит сравнить качество данных, полноту,
> трудозатраты пользователя и вычислительные затраты. Подготовить
> воспроизводимую конфигурацию, инструкции и отчёты об ограничениях.

Это проектируемый scope для согласования, не уже достигнутое состояние
и не окончательное обязательство по договору. Доступность локальных весов
не гарантирует достижение нужного качества на одном ПК. Если качество/
ресурсы/сроки не подтверждаются, ограничения и пересмотр результата должны
быть согласованы до принятия неисполнимых обязательств.

Объём первого года: один образец и выбранный сценарий. Массовая аппаратная
поставка, сертифицированный защищённый ПАК, промышленный SLA и автономное
решение произвольных научных задач не заявляются.

## 5. Дальнейшая приёмка автономного QA — за пределами выбранной сборки/отладки

Таблица ниже относится к перспективному полноценному автономному продукту.
Её нельзя выдавать за уже выбранный годовой объём аппаратного стенда.

| Проверка | Наблюдаемое доказательство |
| --- | --- |
| Полный процесс без внешней сети | В изолированном профиле: импорт нового разрешённого PDF → OCR/текст → индексация → поиск → извлечение/ответ → review → экспорт; все внешние обращения заблокированы/учтены, незаявленного fallback нет |
| Локальные российские ИИ | Реестр всех моделей/версий/лицензий для generation, rewriting, embeddings, reranking и OCR; происхождение и допустимость проверены раздельно |
| Качество | Одинаковые требования/источники, отдельная development и закрытая evaluation части; ошибки/пропуски/отказы сохранены; качество BOX не наследуется от API |
| Производительность | Peak RAM/VRAM, объём контекста, задержка, throughput и одновременные задачи на заявленной конфигурации |
| Эксплуатация | Установка из зафиксированного комплекта, backup/restore, перезапуск, измеренная длительная нагрузка; обновление и перенос данных по регламенту |
| Затраты | Цена комплекта/лицензий/эксплуатации, потребление энергии и сопровождение; API-тариф за токен в BOX не переносится, но токены/вычисления продолжают расходоваться |

Численные требования к качеству/скорости/параллельности утвердить до финального
выбора комплектации и закрытой оценки. Приёмка не должна ограничиваться
одним удачным ответом или лишь запуском модели.

## 6. Как вывести комплектацию и стоимость

1. Уточнить доступную технику и профиль: число пользователей, задачи/день,
   допустимую задержку и объём корпуса/контекста.
2. Проверить development-кандидаты локального ИИ на доступном или отдельно
   согласованном временном ресурсе; сохранить качество, фактические RAM/VRAM,
   context и время. Никакие новые платные прогоны не разрешены этой записью.
3. По измерениям определить требования к GPU/VRAM, RAM, CPU, накопителям,
   охлаждению/питанию, резервированию и гарантии. Учитывать веса и рабочую
   память, а не только число активных параметров MoE. Память нескольких GPU
   нельзя автоматически считать общим пулом без проверки inference-схемы.
4. Составить спецификацию, получить реальные предложения поставщиков и
   расчёт сборки/испытаний. До этого цены компонентов и достаточность
   конкретной суммы не установлены.
5. Подготовить конкретный запрос на согласование оборудования с задачами,
   спецификацией, сметой, альтернативами и условиями дальнейшего использования.
   Запрос не отправлять без отдельного поручения пользователя.

условные 800 тыс. рублей на один экспериментальный комплект:

800 тыс. — условная строка для расчёта сценария, не коммерческое предложение,
не установленная цена ПК и не утверждение, что её достаточно. Увеличение
числа профилей может изменить трудоёмкость команды и испытаний: одинаковые
остальные строки здесь служат только сравнению, не доказательству достаточности.

В примере доля первой строки около 45,83% для 4,8 млн. Это не подтверждение
окончательного выполнения лимита: классификация экспертных/инженерных выплат,
начислений и накладных остаётся открытой. Изменение базы для накладных
пересчитать по правилам организации. Исключить двойную оплату сборки,
интеграции/испытаний, вычислений и гарантийных работ между строками.
Оставшиеся до потолка средства не являются свободным резервом.

Если оборудование не согласуют, API-сценарий может оставаться альтернативой
только при заранее согласованных результатах/сроках. Нельзя по своему
усмотрению заменить принятый договорный BOX на API и объявить обязательства
выполненными. Покупка PC не заменяет финансирования оценки научного качества.

## 8. Коммерциализация — выбранная модель и открытые вопросы

Следующее согласованное решение 17 ноября: одна подписка покрывает одно
рабочее пространство исследовательской группы. Покупатель — организация,
пользователи — сотрудники выбранной лаборатории/подразделения, корпус —
группы. Включённый лимит вычислений общий, потребление учитывается по
пользователям. Число участников и права доступа ещё не заданы; подписка
не распространяется автоматически на всю организацию. Персональный тариф
пока не выбран. Отдельно учитывать затраты хранения, обработки новых
документов и модельных вызовов; это не три платежа и не утверждённые квоты.

- API: утверждённая подписка ARIADNE с включённым лимитом вычислений;
  клиент платит оператору, оператор оплачивает поставщика API. Отдельный
  API-аккаунт клиента не является обязательным условием этой модели.
- BOX: предложенные пользователем поставка и настройка, затем самостоятельная
  загрузка статей клиентом; разовая покупка рассматривается как модель.
  Готовая коммерческая поставка и объём сопровождения не подтверждены.

Цена/период подписки, единицы и размер лимита, условия исчерпания/пополнения,
стоимость хостинга, оператор и условия договора с провайдером остаются открытыми.
Требования к будущей реализации: серверное хранение секретов, изоляция клиентов,
учёт всех модельных этапов, предварительное ограничение и резервирование
расхода параллельных запросов. Это ещё не выполненная проверка безопасности.
Модель оплаты не меняет путь передачи документов и не устанавливает
конфиденциальность, допустимость внешней обработки или право передавать статьи.

Тип покупателя подписки выбран — организация; конкретный покупатель,
цена, маржа, спрос, объём продаж и требования к поддержке пока не подтверждены.
Для BOX отдельно учитываются гарантия, обновления и
ответственность за аппаратный сервис. Экономию полной стоимости владения
относительно API без расчёта нагрузки не заявлять.

## 9. Статус

Changed: сохранены два профиля, обоснование оборудования и пример бюджета;
прежние документы получили ссылки на это уточнение.

Tests run: в текущем уточнении проверены локальные ссылки, согласованность

Limitations: модель/спецификация/цены/качество BOX, согласование закупки,
