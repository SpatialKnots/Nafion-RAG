# Исправление библиографической записи Kondo

Changed:

По запросу пользователя «Давай исправлять причину» исправлена одна запись
`3e970332-cced-4895-b44e-50a48bdc8e17` в локальной PostgreSQL. До исправления
`title="Kond 2025"`, `authors/year/journal=null`. Это была служебная метка,
а не заполненная библиография; точный поиск `Kondo (2026)` не находил статью.

Теперь записаны полное название, полный упорядоченный список восьми авторов,
год выпуска2026 и журнал Advanced Materials. Основание — первая страница
оригинального PDF с DOI `10.1002/adma.202514060`, SHA-256
`615828f87ad5a0d95872524c2bf3e96e5fed696f18b31a9f6903a128728950f3`.
Год взят из печатной ссылки выпуска «Adv. Mater. 2026, 38, e14060»;
copyright2025 и имя файла не использованы как год выпуска. Полный образ
первой страницы визуально просмотрен; свежая текстовая выборка и точные
смещения цитат сохранены. Авторы помечены как source-reviewed correction,
не результат LLM и не независимая экспертная аннотация.

Добавлены только два служебных скрипта исправления/проверки и документация.
Код приложения остался в прежнем freeze `27def498…`; правила точного поиска,
admission, ранжирование, вопросы, PDF, индексы и схемы не изменялись.
Сохранены полный каталог до/после, план, источник и намерение применения.
Пробное обновление было откачено до применения. Перед записью проверены
DOI/hash/исходные поля; строка блокировалась. Последующее чтение всего
каталога подтверждает ровно четыре изменённых поля у одной статьи.

Tests run:

- **63 существующих теста passed**: source-reference resolution, SQL-фильтры,
  bibliography bridge, reference quotes. JUnit сохранён; pytest сообщил
  предупреждение о недоступном каталоге cache. Ruff двух новых скриптов passed.
- **30 свежих подготовок через прежний экспериментальный API**, каждая в
  отдельном процессе с read-only транзакцией и rollback. Внешняя сеть
  блокировалась; реальные OAuth/model calls0, попыток сетевого выхода0.
  Получившиеся native inputs не отправлялись и не создают нового разрешения.
- Все30 запросов однозначно разрешают ожидаемую статью, и все выбранные
  фрагменты принадлежат ей. У Kondo смешение устранено на10/10 вопросах:
  **один готов к отправке, девять сохраняют lexical refusal**
  `insufficient_distinctive_term_coverage`. Nambu:2 готовых/8 lexical refusals;
  Peng:4 готовых/6 lexical refusals. Это подготовка, не новые ответы модели.
- У всех20 Nambu/Peng запросов совпали API inputs, выбранные sources,
  article metadata, native inputs или прежние ответы отказа.19 полных traces
  побайтно прежние. У Peng_04 изменились только два названия Kondo среди
  промежуточных кандидатов; значения scores/order/IDs и все остальные поля
  совпали. Эти дельты явно привязаны к исправленной статье, без изменения
  старых файлов и без удаления диагностических полей.
- Точный поиск `Kondo (2026)` теперь даёт одну статью; `Kondo (2025)` и
  `Kond (2026)` не разрешаются. Нечёткое сопоставление и подмена года не введены.
  Проверено, что существующая projection-политика bibliography refresh
  сохраняет исправленные непустые поля даже при пустом автоматическом предложении.
  Сохранённые manifests прежних30 prepared/live результатов проверены;
  прежний live scope по-прежнему закрыт, remaining allowance0.

Диагностика: первое чтение PostgreSQL отклонено sandbox, затем разрешённое
чтение успешно. Первый plan_v01 остановился до изменения данных: короткая
цитата журнала встретилась дважды. Отдельный plan_v02 использует уникальную
полную строку; старый каталог не был изменён неуспешной пробой. Первый reviewer
отклонил trace Peng_04; его исходник сохранён, review_v02 явно проверяет ровно
две описанные замены заголовка. Первоначальные lint/import/name замечания и
ошибка quoting в дополнительной диагностической команде исправлены; последняя
не выполнила никаких операций. Старые артефакты не перезаписаны.

Limitations:

Исправлена конкретная библиографическая запись, а не реализовано общее
автоматическое исправление неизвестных метаданных. Неизвестные/неоднозначные
другие ссылки по-прежнему требуют отдельной проверки. Производственный поиск
при неразрешённой ссылке сохраняет прежнее fallback-поведение; harness-защита
не объявляется новой защитой обычного `/answer`. Лексические отказы остаются
отдельной проблемой. Полный suite/mypy/browser layout не запускались;
научная точность и качество новых ответов не измерялись. Все30 вопросов уже
раскрыты и используются здесь как регрессия. Независимая оценка остаётся открытой.

Verdict:

Причина `harness_article_scope_stop` на этих вопросах Kondo устранена корректной
библиографией:10/10 подготовок используют только нужную статью. Это не означает
10 успешных или правильных ответов. Следующий отдельный этап — RU/EN lexical
admission с проверкой ложных допусков и отказов; новые LLM-вызовы не выполнены
и автоматически не разрешены. Общий план остаётся75% выполнения, не accuracy.
