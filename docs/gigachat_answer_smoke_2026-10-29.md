## Infrastructure failure and bounded continuation

The first offline preparation stopped on the runner's own overly narrow loopback
guard: Windows asyncio uses an ephemeral loopback socketpair. That guard was
fixed before a successful preparation; no model request occurred.

The initial dispatch `live_v01` then returned HTTP 503 at OAuth:
`GigaChat OAuth request failed (URLError)`, model attempts **0**. A credential-free
TLS probe established sandbox `WinError 10013`; the same verified-TLS probe outside
the sandbox succeeded. This was an environment socket restriction, not evidence
of provider credential rejection.

Preserved that output and original slot. Before continuing, archived its runner,
test and protocol sources, added prospective infrastructure-continuation rules,
ran safety tests and created fresh preparation `prepared_v03`. One immutable child
slot permits only continuation after the unchanged recorded pre-model OAuth
failure. It forbids continuation after any model attempt or if the child exists.
The permitted live run `live_v02` executed outside the sandbox.

Across both dispatch records: **2 OAuth attempts**, the first blocked in the
sandbox; **1 model attempt**. There were no automatic retries within either run,
no model retries, fallback, balance/model-list calls, purchase or scope upgrade.
The total one-model-request authorization is consumed. Do not reset the parent
or child slot to resend this request.

## Limitations

One exposed question and one observed model response; no independent scientific
acceptance, generalized accuracy, provider comparison or billing verification.
Monetary cost remains unknown. The runtime prompt contains **10 complete-page
occurrences**; this tests the existing raw-chunk path and does not pass a compact
context admission policy. Whitespace normalization, extracted formula noise and
irrelevant evidence remain visible. Context-compression instrumentation is still
deferred. ASGI HTTP checks and static link checks do not establish browser UI QA.

Header request IDs are not exposed by the current adapter; the native response
has no ID, so both remain unknown. Code/source hashes and existing local caches
are evidence, not a portable environment lockfile. The full regression suite was
not rerun for this isolated runner; the 2672-case suite belongs to the earlier
runtime-switch report and is not a new result of this smoke.

## Next step

Prepare a minimal, separately tested format fix: make the allowed raw citation
IDs explicit and consider restricting `citation_ids` to the supplied IDs in the
native JSON Schema. Preserve rejection of genuinely unknown IDs; do not silently
strip brackets from arbitrary model output. Endpoint compatibility and any new
live result require their own checks. No production fix or further model call
was performed in this smoke.
