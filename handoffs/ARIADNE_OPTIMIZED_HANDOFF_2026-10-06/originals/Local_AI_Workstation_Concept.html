Локальная AI-станция
Hybrid Local + GPT API

Рабочая станция примерно до 500 000 ₽ для локального запуска больших LLM, RAG, научного Python-кода и вычислительных задач. Пользователь сам выбирает уровень обработки: локальная модель для повседневной работы, GPT API для сложных задач или режим проверки, где локальный результат дополнительно отправляется GPT как экспертному слою.

1. Какие модели эта станция сможет нормально запускать локально

Конфигурация 2× Palit RTX 3090 GamingPro 24 GB + 256 GB ECC RAM особенно хорошо подходит для моделей класса 24–32B: в 4-битной квантизации они обычно помещаются целиком в одну RTX 3090, оставляя вторую GPU свободной для параллельной задачи, embeddings, второго пользователя или другого экземпляра модели. Модели класса 70B уже имеет смысл распределять между обеими RTX 3090.

Практический центр сборки — 30–32B. Это тот класс, где уже получается заметно более сильная локальная модель, но без необходимости постоянно использовать CPU-offload. Для повседневной работы я бы начинал именно с Qwen3-32B или Qwen3-30B-A3B, а GPT API оставлял для запросов, которые ты сам помечаешь как экспертные.

Самый комфортный класс

24–32B

Одна RTX 3090 на модель. Можно держать вторую карту свободной либо запускать второй сервис.

Максимум без CPU-offload

≈70B Q4

Шардирование на 2×24 GB. Контекст и KV-cache нужно настраивать разумно.

256 GB RAM нужны не зря

RAG + offload

Большие индексы, несколько сервисов и экспериментальный CPU-offload моделей крупнее GPU-класса.

Что я не считаю режимом «без проблем»: модели существенно крупнее 70B. 256 GB RAM позволяют экспериментировать с CPU-offload, но скорость уже будет заметно ниже, поэтому такие модели не стоит считать основной целью этой сборки.

GPU-стратегия: целимся в две одинаковые Palit RTX 3090 GamingPro 24 GB. Так проще с физической компоновкой, охлаждением, power limit/undervolt и обслуживанием. Версию GamingPro OC оставляем только как запасной вариант, если вторую обычную GamingPro по сопоставимой цене найти не удастся.

В колонке «Ссылки / варианты» основной выбранный вариант указан первым. Для позиций, где сохранено меньше трёх сопоставимых предложений, добавлена ссылка на точную модель/спецификацию или поиск по точному артикулу.

Важно по VRAM: две RTX 3090 дают 48 GB суммарной видеопамяти, но это не единый физический пул. Для моделей крупнее 24 GB необходим runtime, умеющий шардировать веса между GPU.

3. Концепция машины

Пользователь / интерфейс Open WebUI, браузер, CLI, Jupyter, API-клиенты.
→
Router / Orchestrator Получает выбранный пользователем режим, подключает RAG/инструменты и направляет запрос локальной модели, GPT API или в цепочку проверки.
→
Исполнители Local LLM + Python/Jupyter + RAG + GPT API.
Базовый принцип: режим выбирает пользователь. По умолчанию можно работать локально, а для действительно сложных или важных задач вручную включать GPT API либо режим проверки локального ответа.
Ключевое решение: сложность задачи задаёт пользователь. Router не принимает решение о необходимости GPT API самостоятельно.

Локально

  • обычные диалоги и справочные задачи;
  • RAG по локальной базе документов;
  • суммаризация, форматирование, извлечение данных;
  • генерация и правка кода;
  • первичный анализ таблиц, логов и текстов;
  • подготовка промпта/контекста для внешнего эксперта;
  • работа с чувствительными локальными данными без отправки наружу;
  • научные Python/Jupyter-вычисления и детерминированные процедуры.

Через GPT API

  • сложное многошаговое планирование;
  • критика и проверка локального ответа;
  • методология научных расчётов;
  • поиск противоречий и логических дыр;
  • сложная работа с неоднозначными требованиями;
  • финальная экспертная редактура важных результатов;
  • задачи, где локальная модель не достигает заданного уровня уверенности.

4. Логика ручного выбора режима и передачи запросов в GPT API

Приём запроса. Router получает текст, вложения и метаданные режима.
Выбор режима пользователем. Перед отправкой запроса пользователь выбирает: локальный ответ, GPT API, автоматическое подключение инструментов без оценки сложности или обязательную проверку локального ответа через GPT API.
Попытка локального решения. Local LLM формирует первичный ответ, при необходимости вызывает Python/Jupyter и извлекает контекст из RAG.
Маршрутизация по выбранному режиму. Router не оценивает «сложность» сам. Он просто исполняет выбранный сценарий: local, expert или verify.
Минимизация отправляемого контекста. В API передаётся только нужный фрагмент: постановка задачи, релевантный RAG-контекст, промежуточный локальный результат и конкретная инструкция эксперту.
Сведение результатов. Router объединяет локальный результат и ответ GPT API, сохраняет источники/промежуточные результаты и возвращает финальный ответ пользователю.

Предлагаемые ручные режимы

  • /local — принудительно только локальная модель, без внешнего API;
  • /expert — сразу использовать GPT API как экспертный слой;
  • /tools — локальная модель + RAG/Python/Jupyter; Router сам подключает инструменты, но не решает, нужен ли GPT API;
  • /verify — локальный ответ формируется первым, затем обязательно проверяется GPT API.

На старте необязательно разворачивать все inference-runtime одновременно. Практичный путь — начать с одного основного runtime, Open WebUI, RAG и простого FastAPI-router, а затем добавлять второй runtime только при реальной необходимости.

6. Аппаратная логика платформы

Почему EPYC SP3

  • много PCIe-линий;
  • удобство multi-GPU;
  • 8 каналов DDR4;
  • ECC RDIMM;
  • серверная плата с IPMI/BMC.

Почему 2× RTX 3090

  • 24 GB VRAM на карту;
  • 48 GB суммарно для шардирования;
  • CUDA-экосистема;
  • хорошая цена на вторичном рынке;
  • возможность undervolt/power limit.

Почему 256 GB RAM

  • RAG и большие индексы;
  • CPU-offload;
  • научные задачи;
  • контейнеры/сервисы;
  • апгрейд 4×64 → 8×64 = 512 GB.

7. Проверки перед покупкой

  • EPYC: CPU neutral/unlocked, без PSB vendor lock.
  • H12SSL-I: проверить официальный PCIe slot map, электрические режимы и физическое расстояние между слотами.
  • RTX 3090: OCCT VRAM, температура memory junction/hotspot, отсутствие артефактов и сбросов драйвера.
  • PSU: убедиться в полном комплекте независимых PCIe 6+2 pin кабелей.
  • Корпус: подтвердить реальный fit двух 2.7-slot GPU, кулера и длинного 1600-W PSU.
  • BIOS: Above 4G Decoding и настройки multi-GPU.
  • Электропитание: бытовая линия должна уверенно держать нагрузку порядка 1 кВт и выше.

8. Что ещё не закрыто

  • окончательный физический compatibility audit по официальным мануалам;
  • UPS — нужен ли сразу и какой мощности;
  • нужны ли PCIe-райзеры/дополнительные крепления;
  • второй SSD под модели, embeddings и RAG-кэш;
  • финальная схема airflow и направление 6×140-mm вентиляторов;
  • выбор основной локальной модели и формата квантизации;
  • финальные правила ручного выбора режимов и лимиты расходов GPT API.
